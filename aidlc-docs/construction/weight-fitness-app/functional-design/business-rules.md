# Business Rules

**状態**: ユーザーレビュー待ち  
**Unit**: `UOW-01 weight-fitness-app`

| ID | ルール |
|---|---|
| BR-01 | 業務日付は`Asia/Tokyo`で解決する。端末の異なるローカル時刻で日次記録を別日に移動させない。 |
| BR-02 | 体重はkg、日付ごと最大1件。0以下は不可、小数点以下1桁（0.1 kg単位）。業務上の上限値は設定しない。 |
| BR-03 | 体重の入力・編集は過去日を含む任意の日付で可能。数値以外、非有限値、0以下、0.1 kg刻みでない値を保存しない。 |
| BR-04 | 初回アクセス時、ミッションを1〜15件設定するまで日次利用を開始できない。初期テンプレートは空。 |
| BR-05 | `setupDate`は初回ミッション設定を保存したAsia/Tokyoの日付。ミッション追跡はこの日から始まり、それ以前の日にミッション状態を作らない。 |
| BR-06 | ミッションは全体で最大15件。運動目標は他のミッションと同じ項目として登録・達成管理し、別の運動ノルマ状態は持たない。 |
| BR-07 | Mission Configurationの編集は編集日のミッション状態に適用し、将来日に継続適用する。過去日に保存済みのミッション定義と達成状態は変更しない。 |
| BR-08 | `setupDate`以降は有効ミッションが0件の日を作らない。個別ミッション削除後も有効件数が1件以上であることを検証する。 |
| BR-09 | `setupDate`以降の日次完了条件は、体重あり、かつその日に適用される全ミッションが達成済みであること。 |
| BR-10 | `setupDate`より前の日付はミッション条件をN/Aとする。体重記録があれば日次完了色の対象にできる（Q16-B）。 |
| BR-11 | 食事画像は任意であり、日次完了判定に含めない。 |
| BR-12 | 受理画像はJPEG、PNG、WebPのみ。ファイルサイズは1枚10 MB以下。1日0〜2枚。 |
| BR-13 | 3枚目または非対応形式・サイズ超過の画像は拒否し、既存記録・画像を変更しない。 |
| BR-14 | 画像個別削除前に対象画像と日付を確認する。成功完了と通知する時点で、JSON参照とS3オブジェクトの削除が整合していること。競合・部分失敗は成功扱いにせず再試行可能なエラーとする。 |
| BR-15 | 月JSONは読み込んだバージョンを付けて更新する。期待バージョンが古い場合は更新を拒否し、最新状態を利用者へ示す。 |
| BR-16 | 同時更新では後着更新による自動上書きをしない。利用者が最新データを読み直し、草稿を再適用して再送する。 |
| BR-17 | 料理画像の有無にかかわらず、月間目標は月単位で独立して表示・編集できる。 |
| BR-18 | URLを知る利用者は認証なしで同じデータを閲覧・更新する。閲覧者と編集者の権限分離を行わない。 |
| BR-19 | アプリ内バックアップ／復元と全データ一括削除は提供しない。画像単位の削除はBR-14に従う。 |
| BR-20 | 指定14色以外をUIに追加しない。色は文字・背景・状態を読み分けられる組み合わせで使う。 |
| BR-21 | 通常のアプリデータは月単位JSONとしてS3に保存し、画像データは別の非公開S3オブジェクトにする。S3への全アクセスはバックエンド経由。 |
| BR-22 | S3読み書き失敗時は未保存・未完了を明示し、入力草稿を失わず再試行可能にする。内部S3情報はエラー表示へ露出しない。 |

## Mission Configurationの適用モデル

Mission Configurationは全月に共有される論理JSONで、バージョン・`setupDate`・有効ミッション定義を保持する。月JSONの各日には、その日付で有効だった定義と達成状態のスナップショットを保持する。具体的なS3オブジェクトキーや条件付き書込み方式はInfrastructure Designで定める。
