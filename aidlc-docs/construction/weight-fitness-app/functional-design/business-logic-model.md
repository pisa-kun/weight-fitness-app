# Business Logic Model

**状態**: ユーザーレビュー待ち  
**Unit**: `UOW-01 weight-fitness-app`  
**関連ストーリー**: US-01〜US-11

## ドメインのまとまり

- **Mission Configuration**: 全月で共有する現在のミッション定義と履歴。初回設定日・定義バージョンを持つ。S3上の独立したJSONドキュメントとして保存し、リレーショナルDBは使わない。
- **Month Document**: 1か月分の体重、ミッション状態スナップショット、画像参照、月間目標を持つJSON。S3上の月単位オブジェクト。
- **Daily Record**: Asia/Tokyoの暦日をキーに体重、適用ミッションの状態、画像参照を保持する。
- **Food Image Object**: 非公開S3に保存するJPEG/PNG/WebP画像。月JSONはオブジェクトを参照する。

Mission Configurationを月JSONから分ける理由は、全月で現在の定義を共有しながら、ミッション編集を将来の日に適用し、過去日の内容を固定するためである。両方とも通常アプリデータのJSONであり、保存先は非公開S3とする。

## 初回セットアップとミッションのライフサイクル

1. 初回利用時、利用者は1〜15件のミッションを設定する。0件のまま利用開始できない。
2. 保存成功時の日本時間の日付を`setupDate`としてMission Configurationに記録する。
3. ミッション追跡は`setupDate`から始める。それ以前の日付にはミッション状態を作らない。
4. `setupDate`以降の日ごとに、適用されるミッション定義のスナップショットと達成状態を月JSONに保持する。
5. ミッション定義の編集は編集日（日本時間）以降に適用する。既存過去日の定義・達成状態は変更しない。
6. 運動目標は通常のデイリーミッションとして登録する。独立した運動ノルマや別の達成チェックは持たない。

## 日次記録と完了判定

- 体重は日付ごとに最大1件。kgで正数、小数点以下1桁の精度で扱う。
- `setupDate`以降の日の完了条件は、体重記録があり、かつその日に適用される全ミッションが達成済みであること。
- ミッション設定前の日付では、ミッション条件はN/A。体重が記録されていれば完了色の対象にできる。
- 食事画像は日次完了判定に影響しない。
- 当日の枠線・月間目標・選択日モーダルはカレンダー表示モデルへ反映する。

## ミッション編集と月間JSON

- Mission Configurationは現在の定義、定義バージョン、適用開始日を管理する。
- 更新前に読んだ古いバージョンからの保存は拒否する。最新状態を返し、画面は競合を通知して利用者に再読込・再適用を案内する。
- 後着更新による自動上書きはしない。
- 月JSONは月キーで読み書きし、日ごとのミッション定義スナップショットが後日の設定編集で変化しないようにする。

## 食事画像の添付・削除

- 形式はJPEG、PNG、WebP。1画像10 MB以下。1日あたり最大2枚。
- 添付は形式・サイズ・日別枚数を確認後、画像オブジェクトを非公開S3へ保存し、月JSONに参照を記録する。
- 削除は画面で確認後、対象日JSONと画像オブジェクトを整合させる。競合または部分失敗時は成功扱いにせず、再試行可能な型付きエラーを表示する。
- 個別画像削除は提供するが、アプリから全データ一括削除は提供しない。

## 手動操作の主要フロー

- **初回設定**: 1〜15ミッション入力 → 検証 → `setupDate`付き設定を保存 → 当日以降の日次記録で追跡開始。
- **日次記録**: 日付解決（Asia/Tokyo）→ 体重／ミッション／画像の入力 → 業務ルール検証 → 月JSONおよび必要な画像オブジェクトを保存 → 完了状態を再計算。
- **ミッション編集**: 現在バージョンを取得 → 定義変更を検証 → 新バージョンを適用日付きで保存 → 未来日へ反映し、過去スナップショットは保持。
- **同期競合**: 期待バージョン付き更新 → 古い場合はConflict → 最新値とローカル草稿を保持して再読込・再適用を案内。
- **画像削除**: 対象と確認 → 日付・参照・バージョン検証 → JSON参照とS3オブジェクトの削除を整合 → 完了を表示。

## テスト可能な性質

- **Round-trip (PBT-02)**: 有効なMonth DocumentをJSON化して復元すると、意味上同一になる。
- **Invariant (PBT-03)**: ミッション設定件数は1〜15、日ごとの画像参照は0〜2、体重は正数かつ0.1 kg精度を保つ。
- **Invariant (PBT-03)**: 完了判定は画像枚数に影響されず、適用ミッションの達成状態と体重のみに依存する。設定前の日付ではミッション条件をN/Aとする。
- **Generator Quality (PBT-07)**: 体重、日付、Mission Configuration、Month Document、画像参照を業務制約に従って生成するドメイン生成器を使う。
- **Reproducibility (PBT-08)**: seed記録とshrinkingを有効にし、CIで再現できるようにする。
- 例ベーステストも併用し、上限拒否、設定日前の日付、競合拒否、画像削除の確認を固定シナリオで検証する。
