## カレンダーと日々の記録

### US-01 体重を記録する

選択した日付の体重をkgで記録・修正し、日々の推移を残す。

**受け入れ条件**
- [ ] 1日につき体重を1件保存できる。
- [ ] 当日以外の日付にも記録を追加し、過去の記録を修正できる。
- [ ] 数値でない値や0以下の値は保存せず、入力を修正できる案内を表示する。
- [ ] 保存した記録は日付に紐づき、アプリを再表示しても確認できる。
- [ ] 体重を保存した日は体重項目を完了として扱う。
- [ ] スマートフォンで体重入力を完了でき、対応ブラウザーではPWAとしてホーム画面に追加できる。

**要件参照**: FR-02, FR-07, FR-08, NFR-01

### US-02 運動ノルマを確認・記録する

毎日の運動ノルマを確認し、達成状況を日付ごとに記録する。

**受け入れ条件**
- [ ] 運動ノルマが各日に表示される。
- [ ] 達成状態を操作して記録できる。
- [ ] 別の日の達成状態と混同せず、選択した日付に保存される。
- [ ] 達成済みかどうかを後から確認・変更できる。

**要件参照**: FR-03, FR-07

### US-03 デイリーミッションを確認・達成する

その日のミッションを確認し、各項目の達成状況を記録する。

**受け入れ条件**
- [ ] 設定済みの標準ミッションが毎日に表示される。
- [ ] ミッションごとに達成状態を記録できる。
- [ ] 達成状態は日付ごとに保存され、別の日へ誤って反映されない。
- [ ] 未達成のミッションが残る場合、その日を完了扱いにしない。

**要件参照**: FR-03, FR-05, FR-07

### US-04 標準ミッションを管理する

日々の運動や習慣に合わせて、標準ミッションを追加・編集する。

**受け入れ条件**
- [ ] 標準ミッションを追加できる。
- [ ] 既存の標準ミッションの内容を編集できる。
- [ ] 変更後の標準ミッションが日々のミッション一覧へ反映される。
- [ ] 具体的な初期ミッション名や目標値は、設計で定めた初期設定と一致する。

**要件参照**: FR-03

### US-05 月間目標を設定する

対象月の目標を入力・編集し、月間の取り組みを確認する。

**受け入れ条件**
- [ ] 月間目標を入力・編集できる。
- [ ] 表示中の月に対応する目標がカレンダー上部に常時表示される。
- [ ] 目標の変更後、表示が更新される。

**要件参照**: FR-04

### US-06 カレンダーで日々の状態を振り返る

月の記録と達成状況を見渡し、日付を選んで詳細を確認する。

**受け入れ条件**
- [ ] 月単位のカレンダーを表示できる。
- [ ] 当日は他の日と区別できる枠線で表示される。
- [ ] 体重、運動ノルマ、全ミッションが完了した日を完了色で表示する。
- [ ] 食事画像の有無は完了判定に影響しない。
- [ ] 日付を選ぶと、その日のミッション一覧がモーダルで表示される。

**要件参照**: FR-01, FR-05, FR-07

## 食事画像

### US-07 食事画像を日付に添付する

カメラロールから食事画像を取り込み、該当日の記録と一緒に確認する。

**受け入れ条件**
- [ ] 端末内の画像を選択してWebアプリへ取り込める。アプリ内撮影は行わない。
- [ ] 1日につき0〜2枚を日付に添付・表示できる。
- [ ] 3枚目の追加は拒否し、上限に達したことを知らせる。
- [ ] 画像の取り込みに失敗した場合、既存の記録・画像を壊さず再試行できる。
- [ ] 画像を添付しなくても日次完了判定に影響しない。

**要件参照**: FR-06, FR-07, FR-08

## データとアクセス

### US-08 複数端末で記録を同期する

主に使う端末以外からも、同じ日々の記録を確認・更新する。

**受け入れ条件**
- [ ] 保存済みのJSON記録を別端末から確認できる。
- [ ] 一方の端末で保存した変更が、他方の端末から再読み込み後に確認できる。
- [ ] 同じデータが同時に変更されたとき、更新を無言で失わず、最新状態または競合状態を利用者に示す。
- [ ] 通信や保存に失敗した場合、未保存であることを示し、再試行可能にする。

**要件参照**: FR-08, NFR-03, NFR-05

### US-09 URLからアプリを利用する

アプリのURLを知っている利用者が、ログインせず同じ記録へアクセスする。

**受け入れ条件**
- [ ] アプリのURLを開くとログインを求めず利用できる。
- [ ] URL経由の利用者は同一の記録を閲覧できる。
- [ ] 閲覧者と編集者の権限分離は行わない。
- [ ] S3バケット自体は公開せず、アプリ経由でのみデータへアクセスする。
- [ ] 未認証URLアクセスによるデータ閲覧リスクを、公開前に利用者へ明示する。

**要件参照**: FR-09, NFR-02

### US-10 画面データをS3上のJSONへ保存する

画面で入力した健康記録や目標を、データベースではなくS3上のJSONへ永続化し、次回表示時に読み込む。

**受け入れ条件**
- [ ] 体重、ミッション、月間目標など画面に表示するアプリデータをJSON形式でS3へ保存する。
- [ ] 画面表示時は保存済みのS3 JSONを読み込み、保存後の再表示で同じ内容を確認できる。
- [ ] リレーショナルデータベースを通常データの保存先として使用しない。
- [ ] 画像本体はJSONへ埋め込まずS3オブジェクトとして扱い、JSONに参照情報を保持する。
- [ ] S3読み書きに失敗した場合、未保存状態を利用者へ示し、入力内容を失わず再試行できる。
- [ ] この通常保存フローに、手動JSONインポート／エクスポート機能を含めない。

**要件参照**: FR-08

### US-11 指定パレットで状態を見分ける

指定された色だけを使った画面で、記録・達成状態を見分ける。

**受け入れ条件**
- [ ] 画面の色は要件NFR-04の14色だけから選ぶ。
- [ ] 指定外の色を追加しない。
- [ ] 文字・背景・達成状態の組み合わせを読み分けられる。

**要件参照**: NFR-04

## 網羅性とINVEST確認

- [x] 機能要件FR-01〜FR-09を少なくとも1つのストーリーが参照する。FR-10はバックアップ・復元・削除方針が未確定のため、設計時に確認する
- [x] ユーザー可視のNFRを受け入れ条件へ反映し、技術制約はNFR IDへ参照する
- [x] 画像上限、無効な体重値、同期競合、S3読み書き失敗を含める
- [x] 各ストーリーは独立したユーザー価値を持つ小さな単位として記述する
- [x] 具体的な初期ミッション内容など、要件で未指定の値を勝手に確定しない

## 横断要件のトレース

- **NFR-01**: US-01（スマートフォン操作、対応ブラウザーでのPWA追加）
- **NFR-02**: US-09（URL経由の未認証アクセスとプライバシーリスク）
- **NFR-03**: US-08（同期時の競合・データ整合性）
- **NFR-04**: US-11（指定14色のみ）
- **NFR-05**: 実装時にUS-01、US-08、US-10の純粋関数・JSONシリアライズ往復処理を対象として適用する技術制約
- **NFR-06**: 実装計画上の拡張設定。ユーザー操作ストーリーは作らない
- **NFR-07**: AWS構成・費用・アカウント承認後に実施するデプロイ制約。ユーザー操作ストーリーは作らない
