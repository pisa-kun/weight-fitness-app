# コンポーネント一覧

**状態**: 承認済み  
**配置方針**: 責務別モジュールを単一アプリ／リリース単位にまとめ、運用費用を抑える。具体的なAWS配置サービスはNFR RequirementsとInfrastructure Designで選定する。

## C-01 Web UI

**目的**: カレンダー、記録入力、ミッション、目標、料理画像の表示・操作を提供する。

**責務**
- スマートフォン対応の画面とPWA資産を提供する。
- 選択中の日付・月・ユーザー操作状態を管理する。
- APIの型付き結果を画面表示へ変換する。
- S3へ直接アクセスせず、JSON・画像の送受信をバックエンドAPIへ委譲する。

**インターフェース**: C-02 Application APIを呼び出す。

## C-02 Application API

**目的**: Web UIとアプリケーションサービス間のHTTP境界。

**責務**
- 月単位のJSON、記録、ミッション、月間目標、画像操作を受け付ける。
- 入力を検証可能な形でサービスへ渡す。
- S3の読み書きと画像データ転送をバックエンド内で行い、ブラウザーへS3権限を渡さない。
- 成功・型付きエラーを一貫したレスポンスにする。
- 認証なしという要件に従う。URLを知る人は同じデータ領域を利用できるため、閲覧者／編集者を分けない。

**インターフェース**: C-03 Feature Servicesを呼び出す。

## C-03 Feature Services

**目的**: 機能単位のユースケースを調整する。

**責務**
- 日次記録、ミッション、月間目標、カレンダー表示、料理画像のユースケースを担当する。
- ドメイン入力を検証し、C-04、C-05またはC-08へ読み書きを依頼する。
- 同じ月JSONを更新する処理で競合結果をC-02へ伝える。

**インターフェース**: C-04 Monthly JSON Store、C-05 Image Object Store、C-08 Mission Configuration Storeを利用する。

## C-04 Monthly JSON Store

**目的**: 画面データの通常の永続化を月単位JSONで提供する。

**責務**
- `YYYY-MM`相当の月キーでJSONドキュメントを読み書きする。
- 月JSONに日ごとの体重・達成状態・画像参照と月間目標を保持する。
- 同じ月の更新競合を検出できるバージョン情報をサービスへ返す。
- 手動インポート／エクスポート機能は提供しない。

**インターフェース**: C-06 Private S3 Accessを利用する。

## C-05 Image Object Store

**目的**: 日付に添付された料理画像をオブジェクトとして保管する。

**責務**
- バックエンド経由で画像を保存・取得する。
- 利用者が選択した画像を個別に削除する。
- 月JSONに紐づける安定した画像参照情報を返す。
- 1日最大2枚の業務ルールはサービス層で検証し、画像ストアは保存・取得を担当する。

**インターフェース**: C-06 Private S3 Accessを利用する。

## C-06 Private S3 Access

**目的**: 非公開S3オブジェクトへの最小限のアクセスを提供する。

**責務**
- 月JSON、共有Mission Configuration JSON、画像オブジェクトの読み書きを行う。
- 要件で許可された個別画像オブジェクト削除を行う。
- バケットやオブジェクトを公開せず、バックエンドからだけアクセスさせる。
- SDK／クラウド例外をアプリ共通の型付きストレージエラーへ変換する。

**インターフェース**: C-04、C-05、C-08が利用する。AWSサービス選択、IAM詳細、鍵管理、リージョンはInfrastructure Designで決定する。

## C-07 Result and Error Mapping

**目的**: 成功値または型付きエラーをコンポーネント間で一貫して扱う。

**責務**
- 検証、未存在、競合、ストレージ失敗、画像入力失敗などを型付きエラーとして表現する。
- C-02が利用者向けの安全なエラー応答へ変換する。
- 内部のS3詳細や認証情報を利用者向け応答へ露出しない。

**インターフェース**: C-02、C-03、C-06から共通利用する。

## C-08 Mission Configuration Store

**目的**: 全月で共有する初回設定日、ミッション定義、定義バージョンをJSONとして永続化する。

**責務**
- Mission Configuration JSONを読み書きし、versionと適用開始日を保持する。
- 初回1〜15件のmission setupを保存する。
- 古いversionからの更新を拒否しConflictを返す。
- 月ごとの記録JSONとは別オブジェクトとして扱い、両方とも非公開S3へ保存する。

**インターフェース**: C-03 Feature Servicesが利用し、C-06 Private S3 Accessを介して保存する。

## 配置上の境界

コンポーネントは同一コードベース・同一リリース単位で分離する。Web UIとバックエンドの実行方式・AWSサービス構成は未確定であり、固定稼働費用を避けられる候補をNFR／Infrastructure設計で評価する。非公開S3へのアクセスは必ずバックエンド経由とする。
